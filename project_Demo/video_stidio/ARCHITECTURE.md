## 所有权与线程

`Studio` 拥有项目、历史、YMGUI 控件/状态和媒体引擎。两个常驻后台线程分别处理导入/解码和代理任务，导出时另起任务线程。控件树、subject 和项目仅由 UI 线程访问；线程间通过有界队列/互斥量复制结果，后台不调用 YMGUI。

解码线程拥有 FFmpeg 的 format/codec/frame/scaler，最多保留 4 个媒体解码器，24 帧像素按访问次序替换。新目标替换待处理目标；正在执行的请求可完成，但松手后的序号下限阻止旧结果覆盖最终目标。导入与解码交替调度，连续播放不会永久饿死新素材导入。缩略图使用独立的请求/结果队列，只为代理就绪的可见片段调度，不能向播放器结果通道发布帧；播放和拖头请求优先。

代理线程通过 `posix_spawnp` 和参数数组启动转码，原路径不是 shell 代码。输出目录由 `mkdtemp` 创建；完整成功后才发布代理路径。关闭先取消导出并回收编码进程，再停止预览解码线程、取消并回收代理子进程及文件，最后销毁控件与 subject 的所有者。失败结果只报告失败，不生成替代演示画面。

## 编辑语义

项目时间与源裁剪均使用 25 fps 下的整数帧。片段区间为 `[start, start + length)`；源出点界面显示 `in + length - 1`。片段 ID 在移动/修剪中稳定，分割产生新的右侧 ID。空隙是时间位置差，不伪造成视频片段。

UI 先绘制候选拖放位置；越过真实拖动阈值且释放后才提交一个编辑命令。模型在候选副本上修改，检查所有片段范围、源范围、排序、ID 和容量后整体发布。无效编辑不改变模型和历史。跨轨编辑也只产生一次撤销步骤。

普通移除保留其他片段位置；波纹删除仅将本轨道后续片段移动被删时长。移动只提交目标轨道和时间线位置，保留源入点与长度；仅修剪命令根据边缘位移调整源范围。移动不自动关闭原位置空隙。重叠放置目前拒绝，由 UI 红色候选边框反馈。

## 绑定

- `position`：项目播放头的唯一帧状态，直接绑定时间线播放头。
- `source_position`：源监视器的帧状态，与项目位置分离。
- `mode`：源素材/项目；切换后进度条改绑到对应 position。
- `playing`：绑定播放按钮，播放时钟只推进位置状态。
- `zoom` / `scroll`：几何变化会触发播放头绑定重算，但不会暂停播放或产生用户 seek。
- `revision`：提交编辑后统一刷新时间线与属性。
- `status`：拥有稳定缓冲的字符串 subject。

subject 只存储字符串地址，因此缓冲随 `Studio` 存活，原地更新使用 `Touch`。应用观察者显式摘链，控件观察者由 YMGUI 对象销毁时摘链。

## 文件格式

`VIDEO_STIDIO 1` 文本头记录版本、帧率和数量；素材路径以 UTF-8 字节的十六进制形式记录，以兼容空格、引号、换行。所有数字经有界解析。加载在独立候选项目中校验，成功才替换当前项目。保存使用同目录临时文件、flush/fsync 和 rename。

该格式用于当前原生模型；媒体重定位与素材打包尚未实现。

## 导出的一致性与发布

`st_render_plan` 收集项目片段的起止帧，在边界之间调用与播放器相同的 `st_visible`。合并相邻且源连续的区间，保留黑帧区间。渲染计划中每个区间只保存素材索引、时间线起点、源入点和长度；锁定轨道仍正常渲染，隐藏轨道不参与画面选择。

`StExport` 在主线程复制项目，在工作线程建立独立的 `StDecoder`。预览与导出共用采样代码，输出分别为 RGB565/640×360 与 RGB24/1280×720。编码线程通过非阻塞管道写 RGB24，显式屏蔽自身 SIGPIPE，定期检查取消，避免编码器退出拖垮应用。导出路径与素材身份、已有文件元数据均在启动时检查。

FFmpeg 成功退出、输出文件同步完成且目标状态未变后才发布结果。新目标使用不覆盖现有文件的 `link`，覆盖目标用同目录 `rename`；取消/失败路径均回收进程、管道、日志和临时输出。UI 通过线程安全状态副本更新 `export_running`、`export_progress`、`export_text` 三个 subject，后台不直接访问控件。

当前快照冻结编辑数据，不复制原媒体字节；外部修改素材可能导致任务失败或改变其读到的源内容。项目导出配置目前固定为 SDR、H.264、25 fps、720p，无音频。
