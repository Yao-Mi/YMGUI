# YMGUI 开发进程文档 V2

V2 是 [V1](history/DEVLOG_V1.md) 的直接续集，从第 42 轮开始持续记录开发过程、技术取舍、问题和验证结果。本文与 V1 保持相同定位，是项目的连续“来时路”，不是压缩版 Changelog。

当前事实仍以 [当前状态](当前状态.md)、代码、测试和 CMake 为准；V2 记录一项工作是如何演进到该状态的。V1 已归档，除追溯旧决策或排查回归外不需默认读取。

## 第 42 轮：RGB888 framebuffer 与双格式构建

- 新增 `YMGUI_COLOR_DEPTH=24`：`GYpx` 为 packed 的 3 字节 RGB888（内存顺序 R、G、B），补齐颜色转换、alpha 混合、图片 colorkey、SDL `RGB24` 输出。
- 保留并验证 `YMGUI_COLOR_DEPTH=16` 的 RGB565 路径；像素比较统一使用 `GY_PxEqual`，清零使用 `GY_PX_ZERO`，避免把 RGB888 结构体当整数访问。
- 顶层工程和 `project_Demo` 共用格式选项，构建目录按格式归档：`build/rgb565/...`、`build/rgb888/...`。
- `video_player` 按格式选择 FFmpeg `rgb565le` 或 `rgb24` 原始帧输入。
- 验证结果：顶层 RGB565/RGB888 各 35 项测试全部通过；10 个 `project_Demo` 在两种格式下均构建通过。
- **本轮补充：窗口关闭请求回调**。`SDL_LCD_SetCloseRequestCb(cb, user)` 仅属于桌面 SDL port；收到 `SDL_QUIT` 时，回调返回 0 取消本次关闭，返回非 0 才使 `SDL_LCD_PumpEvents()` 返回 0。未注册时保持旧行为，`Esc` 快捷退出不经过该回调。新增 `demo_close_request`（第一次关闭取消，第二次允许）和 `test_sdl_context` 允许/取消回归覆盖。

## 第 43 轮：GB2312 字模入库 + 文档分层与换卷

**GB2312 字模入库**：用户反馈不知道如何生成 `gb2312_glyphs.bin`，进一步希望直接下载该文件。原仓库在 `.gitignore` 中排除了 blob，只保留生成脚本和码点索引。现移除该排除规则，将 `Demo/gb2312_glyphs.bin` 正式纳入版本管理，普通使用者不再需要先安装 Pillow/Noto CJK 再生成。生成能力仍保留，用于修改字体、字集或光栅化参数。

**字库现状核对**：重跑 `Demo/gen_font.py --cjk --gb2312 --extern --bin` 并与入库 blob 逐字节比较。当前字集不是旧文档所说的 6763 个纯汉字，而是 GB2312 符号/标点区、一二级汉字及额外 `—–·` 共 7448 字形。16×16、4bpp，每字 128 字节，blob 为 953344 字节，SHA-256 为 `c2c42b2c1c2041c158a13b162549a03504202887d8179f476f9ef1a152d51316`。生成脚本帮助、配置头和 Demo 注释中的旧数字同步修正。

**文档分层**：根目录只保留面向使用者的 `README.md` 和维护规则 `AGENTS.md`。API、架构、跨平台移植和代码风格迁入 `docs/`；原 `PROJECT.md` 作为旧项目快照迁入 `docs/history/`；新建 `docs/当前状态.md` 作为当前事实的权威入口。维护者默认先读当前状态，再按任务读专题文档，不因为日常工作重读整卷旧日志。

**当前状态汇总**：用户进一步明确 `当前状态.md` 应当是“精简所有 DEVLOG”，而不只是入口摘要。因此按当前实现重写为完整功能总表：汇总显示/渲染、对象树、输入、内存与裁减、图元/字体、27 个具名控件、状态绑定、插件、平台适配和 10 个完整应用，并单列当前边界。今后“现在有什么”只查当前状态，“当时为什么这样做”才查 DEVLOG。

**DEVLOG 换卷**：用户明确 DEVLOG 仍是连续的项目开发记录，不应被 Git 历史完全取代。因此将第 0～41 轮归档为 `docs/history/DEVLOG_V1.md`，并在 `docs/DEVLOG_V2.md` 从第 42 轮继续。V1 的价值是保留历史上下文，V2 的价值是承接后续过程；`当前状态.md` 则避免日常工作必须从长日志里推断现状。

**验证**：GB2312 blob 可重现生成且与入库文件完全一致；Markdown 本地链接检查通过；根工程完整构建通过，**ctest 35/35**；`git diff --check` 通过。

## 第 44 轮：工具目录归位与自动化验证入口

**生成工具和产物归位**：新增仓库级 `tools/`，将字符/字体生成器从 `Demo/gen_font.py` 迁到 `tools/gen_font.py`，将已入库的外部字模从 `Demo/gb2312_glyphs.bin` 迁到 `tools/gb2312_glyphs.bin`。`Demo/` 继续只承担示例程序，生成器、可再生产物和维护脚本归入工具目录；三角函数表生成器仍留在 `Demo/`，因为本轮只调整字符生成链路。顶层 CMake、8 个使用中文回退字库的完整应用、源码注释和当前文档中的资源路径全部同步更新。V1 及第 43 轮中的旧路径保留为当时事实。

**字库验证自动化**：新增 `tools/verify_gb2312.sh`。快速模式检查入库 blob 的字形数、字节数和 SHA-256；`--rebuild` 模式调用 Pillow 和 Noto Sans CJK，在临时目录重新生成 blob 与 `YMGUI_FontDataGB2312.c`，再分别逐字节比较。这样既能尽早发现资源损坏，也能验证生成器、字形顺序和索引没有漂移。

**仓库级自动化入口**：新增 `tools/check_docs.py` 检查 Markdown 本地链接；`tools/check_repo.sh` 汇总链接、blob、`git diff --check`、关键数量和过期路径检查；`tools/test.sh` 配置、构建并测试一个色深；`tools/test_matrix.sh` 默认覆盖 RGB565/RGB888，`--all-depths` 可覆盖 1/8/16/24bpp。构建并发默认封顶为 8，可通过 `YMGUI_TEST_JOBS` 覆盖，避免高核数但资源受限的环境拉起过多编译任务。用法集中写入 `tools/README.md`，根 README 只保留常用入口。

**验证**：Python 脚本编译检查与 Shell 语法检查通过；Markdown 32 个本地链接全部有效；仓库计数和旧路径检查通过；7448 字形、953344 字节的 GB2312 blob 重生成后与入库文件一致；RGB565、RGB888 根工程均完整构建，两个配置各 **ctest 35/35**；`SDL_VIDEODRIVER=dummy` 下 `demo_font_gb2312` 成功运行 5 帧并从新路径读取字模（40 次模拟 flash 读取）；`git diff --check` 通过。

## 第 46 轮：补齐 GB2312 单字拼音候选

- 明确 `tools/gb2312_glyphs.bin` 只存字模 bitmap，不包含拼音或词频，不能直接充当输入法词库。
- 从系统 IBus table 的拼音数据生成 `project_Demo/chinese_ime/pinyin_gb2312.inc`，覆盖 YMGUI GB2312 字集的 6756 个单字、共 8864 条“拼音→单字”映射，并保留多音字全部读音；应用自有短语词库仍优先，未命中时回退单字候选。
- 英文继续由 YMGUI 虚拟键盘直接输入，中文使用同一 QWERTY 键盘组成拼音；没有引入 Qt、Maliit、Fcitx 或 Rime 运行时。

## 第 47 轮：拼音前缀候选

- 修正输入 `z` 等未完成拼音时候选栏无反馈的问题。精确短语仍优先，未命中时按当前拼音前缀扫描完整 GB2312 单字表，最多显示当前页容量的候选。
- 增加 `z` 前缀自检，确认首字母输入即可得到候选；空组合串保持候选栏清空。

## 第 48 轮：用户习惯频率排序

- 候选排序不再只依赖静态“常用字”表；每次候选上屏都会累加运行时命中次数，后续相同拼音候选按命中次数降序、同频保持原始顺序。
- 统计表固定 64 项、仅驻留 RAM，适配裸机约束；未引入文件系统持久化。自检验证连续选择“尼”后 `ni` 首候选自动调整为“尼”。

## 第 49 轮：全前缀候选参与排序

- 修正候选池过早截断的问题。输入 `z` 或继续输入 `h` 时，先收集全部匹配 GB2312 单字，再按用户命中次数排序，最后按页显示 5 项；不再只对前 16 项排序。
- 候选池容量为 8192 个指针，覆盖当前生成表的全部 6756 条映射和应用短语；候选内容仍由 YMGUI Button 渲染。

## 第 50 轮：候选分页懒排序

- 前缀查询改为按页增量选择：保存当前拼音和已选候选，第一页只扫描并选出前 5 项；点击下一页时再从完整匹配集合中选出下一批，已选项跳过。
- 这样 `z`、`zh` 等前缀仍可覆盖全部匹配字集和用户频率排序，但不会在输入首字母时一次性构造完整候选排序结果。

## 第 51 轮：多音字读音补全

- 修正生成器只取每个字第一个拼音的问题；现在保留 IBus 表提供的全部读音，例如“曾”同时支持 `ceng` 和 `zeng`。
- 映射总数从 6756 条增加到 8864 条，增加 `zeng` 回归测试并确认“曾”可在懒分页中找到。

## 第 52 轮：常用短语与首字母缩写

- 明确单字拼音表不会自动产生词语候选；新增应用层短语表入口，补充 `wm -> 我们` 等首字母缩写，避免只输入每个音节首字母时完全无提示。
- `wm` 回归测试验证首候选为“我们”；更大规模的短语/用户词库仍应作为独立数据文件生成，不混入字形 blob。

## 第 53 轮：短语与单字合并排序

- 因此输入 `wo`、`wm`、`ni` 等组合时，词语和单字会共同按用户命中次数排序，不再分成两套候选列表。

## 第 59 轮：明确拼音词典与许可兼容

- 推翻“从单字默认读音拼出词语拼音”的临时生成方式。曾验证 libpinyin model20 能提供明确音节和权重，但其模型为 GPL-3+，不适合直接嵌入 Apache-2.0 仓库；最终改用同为 Apache-2.0 的 `rime-pinyin-simp`。
- 新增 `tools/gen_ime_dict.py`，从 Rime 词典生成 7291 条单字读音和 30000 条明确拼音词语。运行时删除手写短语、常用字和特殊词条数组，单字/词语统一按用户命中次数优先、词典初始频率兜底进行懒分页选择。

## 第 60 轮：音节感知短语匹配与完整 Rime 词表

- 替换第 54 轮的任意字符子序列规则。短语查询现在只允许把输入串切成连续音节的非空前缀：`wo'men` 可由 `wm`、`wom`、`wme`、`wome` 或 `women` 命中，`wn`、`wem` 等跨音节跳字母输入不会误命中。
- 取消生成器默认截取 30000 条词语的上限。Apache-2.0 `rime-pinyin-simp` 经 YMGUI GB2312 码点过滤后保留全部 47278 条合法词语；运行时仍按需扫描并只缓存用户请求的候选页，不因词表扩大而一次性排序全部结果。
- 候选只读视图按五个稳定槽位分别裁剪，长词不会覆盖相邻编号或右侧翻页按钮；候选缓存增加容量边界保护，状态栏显示页码而不把当前缓存的 5 项误报成候选总数。用户词频项扩到可完整保存 8 个汉字的 UTF-8 词语，长词选择也能正确参与学习排序。
- `tools/check_repo.sh` 增加输入法数据检查：固定验证 7291 条单字读音、47278 条词语以及“我们/音乐/重庆/曾(ceng/zeng)”关键记录。自测新增音节组合正例、非法子序列反例，并逐项确认 `wom/wome/wme` 的首候选确为“我们”。
- 验证：RGB565 与 RGB888 独立构建通过；RGB565 30 帧无头自测通过；仓库检查和 `git diff --check` 通过。

## 第 61 轮：词条分段组合候选

- 排查 `kknd` 不出现“看看你的”：Rime 源词典分别包含 `看看 = kan'kan/kk` 与 `你的 = ni'de/nd`，但没有“看看你的”整句；此前引擎只查询单条词典记录，不具备桌面输入法常见的分词组合层。
- 增加受限束搜索：沿输入串按音节前缀匹配已有词条，用组成项平均词频和分段数惩罚为组合候选赋初始分数，再与直接词语、单字以及用户选择次数进入同一套排序。该机制从生成词库动态组合，不维护句子特例数组。
- 组合单元同时接受首字母、完整拼音和每音节前缀混输；`kknd` 与 `kankannide` 的首候选均验证为“看看你的”。进一步把单字表接入组合搜索并取消四字母启动门槛，`kkn` 可由 `看看 + 你` 得到首候选“看看你”。组合束宽固定为 6、最多保留 12 个预测项，控制 RAM 和每次按键的搜索量；直接词典候选仍按原有懒分页覆盖全部匹配记录。
- `tools/check_repo.sh` 增加“看看”和“你的”源词条校验；用户词频字符串容量扩大到 96 字节，可学习组合后的较长候选。

## 第 62 轮：可扩展用户词库

- 新增 `project_Demo/chinese_ime/user_phrases.tsv`，每行以制表符填写“词语、分音节拼音、初始词频”。`tools/gen_ime_dict.py` 默认自动合并该文件，也支持重复传入 `--extra-dict` 合并多个外部 TSV；词语数据仍由生成器进入 `.inc`，不在 C 源码维护手写数组。
- 用户词库支持 1 个单字或最长 31 字的词语，接受空格或单引号分隔音节；生成时严格检查音节只能含 ASCII 字母、汉字必须存在于 YMGUI GB2312 字形索引、词长必须等于音节数、词频必须在 uint32 范围。错误会带文件名和行号终止，不会静默漏掉自定义词。
- 空的默认用户词库重新生成后仍为 7291 条单字读音、47278 条词语；RGB565 构建和包含 `kkn/kknd/kankannide` 的无头自测通过。

## 第 63 轮：按文字宽度动态分页与单字母单字优先

- 删除候选区固定五等分槽位和 `页号 * 5` 下标。当前页从排序缓存的起始位置出发，用默认字体的真实像素宽度依次装入候选，最多支持数字键 `1..9`；下一项放不下时不绘制、不截字，完整成为下一页首项。上一页通过已缓存候选重新推导页边界，因此动态页长不会造成重复或漏项。
- 懒加载继续有效：布局只要求生成当前页以及用于判断溢出的下一项，不提前排序全部候选。状态保存当前页起始位置、实际项数和页码；回车、空格、数字选择与前后翻页全部改用动态页索引。
